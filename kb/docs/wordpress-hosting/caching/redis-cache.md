[Redis](https://redis.io/topics/introduction) is an open-source, in-memory data structure store. In the context of WordPress, Redis can be used to store the values generated by [WordPress’ native object cache](https://developer.wordpress.org/reference/classes/wp_object_cache/) in a persistent manner so that cached objects can be reused between page loads.

Many managed Redis solutions run your cache on a totally separate network from your website, often located thousands of miles away. In contrast, Kinsta’s Redis add-on installs a dedicated 2GB Redis instance within the same container as your WordPress site. This architecture ensures that Redis, your PHP engine, and the database all operate on the same physical machine, enabling:

- Extremely low latency.
- Request round-trips in microseconds, not milliseconds.
- Minimal data transit and no external bottlenecks.
- Faster cache performance.

By eliminating external network calls, this local integration is especially beneficial for resource-intensive applications such as WooCommerce stores, membership sites, or high-traffic WordPress installations.

Using a persistent object cache such as Redis cache allows for the **reuse of cached objects** rather than requiring the [MySQL database](https://kinsta.com/docs/wordpress-hosting/database-management/restore-import-mysql-database/) to be queried a second time for the same object. The result is that Redis can reduce the load on a website’s MySQL database, simultaneously decreasing the response time of the site and increasing the site’s ability to scale and handle additional traffic.

## Sites that will benefit most from Redis cache

At Kinsta, [page caching is built in](https://kinsta.com/blog/wordpress-cache/) for all sites on our platform. However, there are some sites that don’t make great use of page caching: some ecommerce sites, membership sites, forums and discussion boards, blogs with extremely active comment sections, and other types of highly dynamic websites.

These highly dynamic websites that cannot make good use of page caching are potential candidates for a persistent object caching option such as Redis.

Redis will generally not help the load time of static blogs, informational business websites, and news websites unless the sites make very poor use of our page caching.

### Redis plugin

The Redis caching add-on installs the Redis Object Cache plugin by default. This is an open-source plugin that is available on [WordPress.org](https://en-gb.wordpress.org/plugins/redis-cache/). Redis also offers [Object Cache Pro](https://objectcache.pro/), which includes debugging tools, memory optimization, and premium support.

If you already use a different plugin to integrate with Redis, such as WP-Redis, or want to use a different plugin on your site to integrate Redis with WordPress object caching, you must disable the Redis Object Cache plugin from the Plugins section of your WordPress WP Admin panel. You can then use or install a Redis plugin of your choosing from the plugin repository; this will cause a warning to appear within **Caching** > **Redis**, which you can ignore. **We do not recommend switching to the Redis Object Cache plugin if you currently have a different Redis plugin working on your site.** Redis may not function properly if a suitable plugin is not installed.

If the Redis Object Cache plugin does not install when you enable the add-on or if it has been removed, you can reinstall the add-on within **Caching** > **Redis** > **Reinstall**.

![Reinstall the Redis Object Cache plugin.](https://kinsta.com/wp-content/uploads/2023/11/wordpress-redis-cache-reinstall.png)

Reinstall the Redis Object Cache plugin.

If you see an error that WordPress is not available, you should reinstall WordPress and try again; this is usually due to a Bedrock or other non-Standard WordPress installation with a custom public web root (document root). Start a new chat with our [Support team](https://kinsta.com/docs/support/contact-support/), and they can add a new `wp-cli.yml` file to the `~/public` directory, with the path pointing to the site’s WordPress installation.

## Important notes

- If your site has both a [staging](https://kinsta.com/docs/wordpress-hosting/staging-environment/) and a live environment and your staging site is no longer needed, please delete it. It can then be recreated following the installation of Redis on the live site. If your staging site cannot be deleted, it will be necessary to add Redis (and the Redis plugin) to the staging site container. If this is not done, the next time staging is pushed live, the Redis installation in the LIVE environment will be overwritten and removed.
- Redis cache details may not be reported correctly in the [Kinsta’s APM](https://kinsta.com/docs/wordpress-hosting/wordpress-monitoring/apm-tool/) tool if you use a plugin other than [WP Redis](https://wordpress.org/plugins/wp-redis/) or [Redis Object Cache](https://wordpress.org/plugins/redis-cache/). This doesn’t mean that Redis isn’t working. This happens because we may not be able to collect and show Redis data from other plugins in the APM tool.
- If you create an empty WordPress or staging environment and enable the Redis caching add-on, it won’t automatically be active on the new empty environment. To enable Redis caching, you’ll first need to install WordPress on the empty environment, [disable the add-on](#disable-the-redis-caching-addon) on the site, and then re-enable it.

## Using Redis with a WordPress website

- Once Redis has been installed and integrated with your site with a plugin, it will run silently in the background.
- It is critical that you test your site thoroughly after enabling object caching, being careful to review all critical processes on your website with multiple user profiles to ensure that cached objects aren’t being reused incorrectly.
- If you find that cached objects are being used incorrectly, it may be possible to exclude specific groups of objects from object caching with the [wp_cache_add_non_persistent_groups](https://developer.wordpress.org/reference/classes/wp_object_cache/#wp_cache_functions/) function. Manipulating object cache performance is outside the scope of Kinsta’s support for Redis and will require the involvement of a qualified WordPress developer.

## Connect your database to RedisInsight

[RedisInsight](https://redis.io/docs/connect/insight/) allows you to visualize your database and perform GUI- and CLI-based interactions in Redis.

1. [Download](https://redis.com/redis-enterprise/redis-insight/), install, and launch RedisInsight.
2. Click **Add Redis database** > **Connection Settings** > **Security**.
3. To connect to RedisInsight, you’ll need the following pieces of information from the **Primary SFTP/SSH user** section of each site’s **Info** tab within [MyKinsta](https://my.kinsta.com/):
   - host/server address (IP address)
   - port (we take security seriously here at Kinsta, each site uses a different port)
   - username (SFTP Username, not your email address)
   - password
     ![SFTP/SSH credentials.](https://kinsta.com/wp-content/uploads/2023/11/wordpress-sftp-ssh-info-1.png)

     SFTP/SSH credentials.
4. In RedisInsight, select **Use SSH Tunnel**. In the section below, enter your **Host**, **Port**, **Username**, and **Password** from MyKinsta, and click **Add Redis Database**.
   ![Enter your MyKinsta SSH credentials to connect to RedisInsight.](https://kinsta.com/wp-content/uploads/2023/11/redisinsight-database-connection-1024x800.png)

   Enter your MyKinsta SSH credentials to connect to RedisInsight.

## Clearing Redis cache

You can clear the cache in MyKinsta, in your WordPress dashboard, with WP-CLI, or with SSH.

### Clear cache in MyKinsta

To clear the Redis cache for a single site, go to**Sites** > ***sitename*** > **Caching** > **Server Caching** > **Clear cache**. Clearing the site cache clears the Redis object cache. This also clears the [edge cache](https://kinsta.com/docs/wordpress-hosting/caching/edge-caching/).

To clear the Redis, [server](https://kinsta.com/docs/wordpress-hosting/caching/site-caching/), [CDN](https://kinsta.com/docs/wordpress-hosting/wordpress-cdn/kinsta-cdn/), and [edge cache](https://kinsta.com/docs/wordpress-hosting/caching/edge-caching/) together for one or more sites, including staging sites, at once, go to the **Sites** page, select the checkboxes next to the sites you want, click **Actions**, then **Caching**, and choose **Clear cache**.

![Clear the server cache on the Caching tab in MyKinsta.](https://kinsta.com/wp-content/uploads/2023/11/wordpress-server-caching-clear-cache.png)

Clear the server cache on the Caching tab in MyKinsta.

### Clear cache in your WordPress Dashboard

With the [Kinsta MU plugin](https://kinsta.com/docs/wordpress-hosting/kinsta-mu-plugin/) (installed by default on all Kinsta-hosted sites), you can purge object cache (and other types of cache) in your WordPress dashboard. Log in to your WordPress dashboard and do one of the following:

- Click the **Clear All Caches** button on the **Kinsta Cache** plugin page in your WordPress dashboard.
- Click the **Clear Caches** link on the WordPress admin toolbar.

Either of these methods will clear object caching and site cache (aka full-page cache).

![Clear cache in WordPress with Kinsta MU plugin.](https://kinsta.com/wp-content/uploads/2023/11/wordpress-muplugin-clear-caches.png)

Clear cache in WordPress with Kinsta MU plugin.

### Clear cache with WP-CLI

[Connect to your server with SSH](https://kinsta.com/docs/wordpress-hosting/connect-to-ssh/) and navigate to your site’s document root:

Copy

```
cd public
```

If the Kinsta Must Use (MU) Plugin is installed on the site, you can clear the Redis object cache with this command:

Copy

```
wp kinsta cache purge --object
```

To clear **all** cache, add the `--all` flag:

Copy

```
wp kinsta cache purge --all
```

Exit SSH with the following command:

Copy

```
quit
```

### Clear cache with SSH

Connect to your server with [SSH](https://kinsta.com/docs/wordpress-hosting/connect-to-ssh/) and flush the Redis cache with the following command:

Copy

```
redis-cli flushall async
```

Exit SSH with the following command:

Copy

```
quit
```

## Limits to Kinsta’s support for Redis

Kinsta’s support for Redis is limited to installing Redis and any required dependencies in the site container and ensuring that Redis is available for use by WordPress. Integrating Redis with your website and excluding specific groups of objects from the cache is the responsibility of each website owner. If you need assistance with the proper integration of Redis with your website, you will need to retain the services of a qualified [WordPress developer](https://kinsta.com/blog/hire-wordpress-developer/).

## Disable the Redis caching add-on

To remove this add-on, within the **Add-ons** page, under **Redis caching**, click **Disable** > **Disable Redis add-on**.

You can also remove the Redis caching for multiple sites at once. From the **Sites** page, select the checkboxes next to the sites you want, click **Actions**, then **Caching**, and choose **Change Redis caching**.

If you remove the Redis caching add-on and you’re in the first 30 days of your WordPress Hosting plan, a prorated fee for the add-on will be added to your next invoice for the time period it was enabled. If your WordPress Hosting plan has been active for more than 30 days, you will receive a prorated credit for the add-on fees to your Account Balance for the remaining days of the current billing period. The credit is automatically used to offset money owed to Kinsta on your next invoice. For more information, refer to our [WordPress Hosting Money-Back Guarantee](https://kinsta.com/docs/service-information/money-back-guarantee/).
